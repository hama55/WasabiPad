# GFMをMarkdown互換基準にする

WasabiPadのMarkdown表示はGitHub Flavored Markdown（GFM）を互換基準とし、`remark` / mdastを解析基盤にする。エディタとプレビュー間の位置対応は、解析木が持つ原文オフセットを唯一の基準にする。同じ表示文字列を文書全体から検索して位置を推測しない。段落内の通常改行（softbreak）を`<br>`として表示するかどうかは設定可能にし、空行はMarkdown標準の段落区切りに任せる。生HTMLの許可範囲とサニタイズは固定仕様として維持する。

## Considered Options

- Markdown描画後に同じ文字列を検索してカーソル位置を当てる: 同じ語が複数ある文書では別の出現位置へ結び付くため採用しない。
- markdown-itのインライン処理を独自拡張して位置情報を補う: 描画用トークンとソース位置を別々に追跡する仕組みを持つことになり、Markdown構文の変換との同期が必要なため採用しない。
- `remark` / mdastの位置情報を使う: ブロックとインラインノードの原文範囲を解析器から取得でき、GFM拡張と同じ解析木からDOMへの対応を組み立てられるため採用する。
- WebView2だけでMarkdownを解釈する: WebView2はHTML/CSS/JavaScriptの表示基盤でありMarkdown解析を行わないため採用しない。
- 空行を入力行数どおり独自要素へ変換する: 他のMarkdown環境と段落構造が異なり、外部アプリで開いたときの差を増やすため採用しない。

## Source Position Mapping

解析木ノードの`position.start.offset` / `position.end.offset`を原文位置の基準にする。通常テキストとコードブロックはノード固有の原文範囲を左から順に消費し、バックスラッシュエスケープ、文字参照、フェンスや字下げの除去、インラインコードの変換に対応する範囲をDOMへ付ける。`<br>`に変換される改行も要素に原文範囲を付け、プレビュー上の改行前後を原文の境界へ戻す。文書全体で描画文字を検索しないため、同じ文字列が繰り返されても出現箇所を取り違えない。プレビューからエディタへ戻るときも同じDOM範囲を使う。

Markdown構文記号のようにプレビューに文字として現れない位置は、対応する表示範囲の境界へ寄せる。変換によって原文と表示の文字数が一致しない単位（例: `&amp;`から`&`）も、その単位の開始または終了へ対応させる。

## Consequences

通常改行の表示は設定画面のプレビュー項目から即時切り替えでき、設定値はJSONへ保存される。既定値は`breaks: true`とし、段落内の改行入力をそのまま表示できる。`breaks: false`では標準softbreakを使う。表、2個以上のチルダによる取り消し線、リンク自動認識は`remark-gfm`で維持し、GFM以外のサービス固有拡張は追加しない。

AST位置と各テキスト変換をDOMへ渡すため複数のremark/rehype依存が必要になる。パーサー更新や追加のMarkdown拡張時は、重複文字列、エスケープ、コード、GFM、生HTML安全性の回帰テストを通す。
