# 段階プレビューと機密アーカイブのキャッシュ境界を分ける

WasabiPadのプレビューは、すべてのページや画像の準備を待たず、本文または最初に必要なページを初回利用可能表示として先に表示する。Markdownの画像は表示領域に近いものから少数並列で読み込み、PDFは7zから一度展開したデータを同じプレビューで再利用して二重展開を避ける。通常ファイルとパスワードなし7zでは、展開済みPDF・画像や表示用派生データを外部キャッシュへ保存でき、保存場所・容量・削除操作を設定画面から確認できる。パスワード付き7zは機密アーカイブとして扱い、復号済みデータをアーカイブ外の永続キャッシュや一時ファイルへ保存せず、表示中の一時的なメモリ利用だけを許可する。7z内へキャッシュを保存する方式は将来の選択肢とするが、通常の自動キャッシュとは分ける。

7zの並列化は、1つのPDFエントリを分割して展開する方式を採用せず、同じ書庫内は書庫単位ゲートで1件ずつ、別書庫間だけ最大3件までに制限する。これにより、solid構成で同じブロックを複数プロセスが重複展開する競合を避ける。WasabiPadからの7z作成・再圧縮機能はこの判断に含めず、既存7zの読み出し改善を優先する。

## Considered Options

- すべての資産の読み込み完了後に表示する: 画像の多いMarkdownで待ち時間が画像数に比例し、初回操作を遅らせるため採用しない。
- すべての文書でアーカイブ外の永続キャッシュを使う: パスワード付き7zの復号済みデータが機密境界の外へ出るため採用しない。
- どの文書にも永続キャッシュを使わない: 機密性は保てるが、通常文書やパスワードなし7zを再度開くたびに展開・デコードを繰り返すため採用しない。
- 1つのPDFまたはsolidブロックを無制限に並列展開する: 圧縮ストリームを分割できず、同じデータの重複展開やCPU・メモリ競合を招くため採用しない。
- 開くたびに元の7zへ自動的にキャッシュを書き戻す: アーカイブの更新、再圧縮、署名・ハッシュの変更を伴い、閲覧操作としては副作用が大きいため採用しない。

## Consequences

初回利用可能表示までの時間を短縮し、Markdown画像の遅い取得やPDFの二重展開を利用者から隠さずにバックグラウンドへ移せる。通常ファイルとパスワードなし7zのキャッシュは利用者が場所と容量を確認・管理でき、元データの変更時は再利用しない。機密アーカイブは外部キャッシュを持たないため、solid構成や初回展開の特性によっては数十秒かかる可能性が残る。その場合は2秒を保証せず、進捗と段階表示を優先する。展開は同一書庫1件、別書庫最大3件を上限とする。
