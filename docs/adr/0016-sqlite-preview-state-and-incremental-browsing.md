# SQLiteプレビューの状態を維持し、段階読込で閲覧する

SQLiteプレビューは、全画面の切替でプレビューpayloadを再送して再生成してはならない。既存iframe内の選択対象、表示位置、読込済み行を維持するため、全画面状態だけを既存の全画面状態メッセージで通知する。

## 決定

- 選択中のテーブルまたはビュー、表示位置、横スクロール位置は、同じプレビューを閉じるまで保持する。再読み込みまたはファイルを閉じて開き直した後には復元しない。
- ビューは通常の表と同じく結果行を表示する。選択中のビューには、`sqlite_schema` から得る `CREATE VIEW` 定義SQLを上部で展開表示する。JOIN先の依存グラフやSQL解析は作らない。
- 選択対象の総行数は、選択または再読み込み時だけ正確な `COUNT(*)` で取得し、`表示中 / 総行数` として表示する。スクロールで追加する各ページでは再集計しない。
- 設定「SQLiteプレビューの表示行数」は、初回読込・段階読込・表示位置移動時の取得単位を表す。初期値は100、正の整数、上限なしとする。
- 「さらに表示」は廃止する。総行数を利用したSQLite専用のウィンドウ表示で、スクロール位置の周辺だけをDOMに置き、近づいた範囲を `LIMIT` / `OFFSET` で読込む。巨大テキスト用 `VirtualEditor` は流用しない。
- 数字入力は「指定行」ではなく「表示位置へ移動」とする。現在のSQLite取得順における一時的な位置であり、DB更新、再読み込み、再オープン後に同じレコードを指す保証はしない。
- 自動更新はしない。追加読込または移動時に外部アプリがDBを変更していれば、その時点で取得した範囲に差異が出る可能性を許容する。DB接続の常駐、DBコピー、独自スナップショットは作らない。

## 却下した選択肢

- 全画面切替時にSQLite専用の選択状態を親画面へ保存する: 全プレビューを再生成しない既存メッセージ経路の方が小さく、行とスクロール位置も同時に守れるため採用しない。
- JOIN依存グラフ: SQLite方言のSQL解析と曖昧な依存関係の表現が必要になり、閲覧専用プレビューの範囲を超えるため採用しない。
- 取得順を恒久的な行番号にする、または並び替えUIを作る: 表・ビュー・外部更新をまたぐ一意な順序を一般には導けず、SQL機能へ拡大するため採用しない。
- 巨大テキスト用 `VirtualEditor` の再利用: mmap、編集、キャレットを前提とし、SQLiteのページ照会には適合しないため採用しない。

## 結果

SQLiteプレビューは編集せず大量レコードを閲覧できるが、行番号はナビゲーション上の一時的位置である。実装担当は [SQLiteプレビューの状態保持と段階閲覧の実装計画](../plans/0017-sqlite-preview-state-and-incremental-browsing.md) を正とする。
