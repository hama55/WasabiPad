# 連携エディタ・連携プレビューの境界を保存済み実ファイルに限定する

## Context

WasabiPad の編集領域とプレビュー領域を、利用者が選んだ別アプリと連携できるようにする。編集とプレビューでは必要なアプリや対応形式が異なるため、単一の「外部アプリ」設定では用途を表せない。また、仮想項目や未保存内容を一時ファイルとして外へ渡すと、同期矛盾や機密情報の漏えいが起きる。

## Decision

- 編集用を **連携エディタ**、表示用を **連携プレビュー** として別の設定対象にする。
- 形式ごとに連携先を選べるようにし、未設定時は WasabiPad の標準編集・標準プレビューを使う。
- 外部連携の対象は、保存先を持つ通常の実ファイルで、現在の内容が保存済みの場合に限る。
- 未保存文書、仮想項目、機密アーカイブ、実拡張子と有効形式が異なるプレビューは外部へ渡さない。
- 既存の「Windowsアプリで開く」とは用途を分ける。「Windowsアプリで開く」はアプリ選択画面を表示し、連携設定は編集・プレビュー用途を選ぶ。
- 連携コマンドの設定は登録コマンドとは分離し、既存のファイル値置換と外部コマンド実行を再利用する。起動コマンドは利用者が編集する完全な Windows コマンドラインとし、`{file}` を対象ファイル位置として扱う。
- 設定画面には連携用の専用カテゴリを設け、編集×有効拡張子・プレビュー×`ViewerFormat` ごとにコマンドを直接設定する。再利用可能なアプリプロファイルや別の識別子管理は追加しない。
- 連携アプリは文書を開いたときに自動起動せず、既存の標準機能を維持したまま、エディタまたはプレビューの操作メニューから明示的に起動する。
- 連携エディタの形式キーには既存の有効拡張子を、連携プレビューの形式キーには既存の `ViewerFormat` を使う。新しい形式体系は作らない。
- 連携先が保存した変更は既存の外部変更検知・再読込・競合処理に任せ、WasabiPad と連携先のライブ同期は行わない。
- コマンド不備や起動失敗は通知し、現在の WasabiPad 画面を維持する。標準機能への自動フォールバックや再試行は行わない。
- 第2段階では外部ウィンドウの位置・サイズ・最大化・最小化・追従・終了制御、および外部プロセスの所有・再利用・終了管理を行わない。

## Consequences

外部アプリへ未保存内容を同期する仕組みや、仮想項目用の一時ファイル管理は追加しない。連携先が設定されていない形式は既存の標準機能で動作し、外部連携の失敗でもファイルビュー側は継続できる。自動起動とウィンドウ制御を後段に分けることで、第2段階の変更範囲を設定と明示起動に限定できる。

## Rejected alternatives

- 登録コマンドをそのまま連携設定に使う: メニュー用の用途と形式別の連携先を混同し、安定した設定識別子もない。
- 未保存内容を一時ファイルで外部へ渡す: 保存状態との同期と機密情報の扱いが複雑になる。
