# 外部プレビューの再利用をセッション内保持と明示保存の2層に分ける

外部プレビューの生成物再利用は、標準プレビュー向けの `プレビューキャッシュ` とは分離し、寿命と鮮度判定が異なる2層で管理する。起動をまたぐ自動キャッシュによる一時領域の肥大化や古い結果の誤表示を防ぎつつ、重い外部変換の繰り返し実行を回避するためである。

1. **セッション内保持（`外部プレビュー生成物`）**: アプリ起動中に生成した外部プレビュー生成物は `外部プレビュー一時保存先` に件数・容量上限を設けず保持し、同じ入力ファイルで再変換が成功したときのみ旧一時生成物を削除して最新1世代へ置き換える。再利用時は入力ファイル内容の SHA-256 ハッシュと外部プレビュー設定（実行ファイル・引数・出力形式）の一致を必須とし、アプリ終了時に一括削除する（強制終了時は次回起動時の既存 stale 清掃で回収する）。
2. **明示的永続化（`保存済み外部プレビュー`）**: 利用者がプレビューヘッダーの保存操作で明示指示したときのみ、元の文書と同じフォルダに `<元ファイル名（拡張子込み）>.wasabi-preview/`（例: `song.abc.wasabi-preview/`）を作成し、入口ファイル（`index.html` または `index.svg`）と付属資産一式を永続化する。次回以降は鮮度確認を行わず、選択中の出力形式と一致する入口ファイルが存在すれば優先して表示する。

読み込み優先順位は例外を設けず、**`保存済み外部プレビュー` → `同じフォルダのプレビューファイル` → セッション内保持の `外部プレビュー生成物` → 新規実行** とする。`保存済み外部プレビュー` の表示中に利用者が「更新」を押した場合は一時保存先へ再変換して表示するにとどめ、保存済みフォルダは自動上書きしない（上書きは明示的な再保存＋確認ダイアログでのみ行う）。`<元ファイル名>.wasabi-preview/` はファイルツリー上で通常フォルダとして扱い、アプリ内に専用の削除操作は設けない。
