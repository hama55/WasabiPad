# 形式指定では有効拡張子を実ファイル名から分離する

ファイルツリーとエディタ文書操作メニューの「形式を指定して開く」では、実ファイル名と保存先を変えず、利用者が選んだ拡張子を現在の表示に限った有効拡張子として扱う。エディタからはアーカイブ内の仮想項目も対象にし、アーカイブ名と内部パスを保持したまま開き直す。偽装の有無を判定する専用モードは設けず、閲覧、編集、アーカイブ更新、HTMLの外部ブラウザ起動を含め、同じ拡張子を持つ通常ファイルと同じ規則を適用する。画像の「自動判別」は内容から有効拡張子を決め、判別不能時は現在表示を維持して失敗を通知する。実ファイルの名前変更や一時コピーを避けながら、拡張子を意図的に変えたファイルを通常機能で扱えるようにするため、この構成を採用する。

## Considered Options

- 実ファイルを一時的に名前変更する: 外部参照、監視、保存先を壊す可能性があるため採用しない。
- 選択した拡張子の一時コピーを作る: 編集結果と原本が分離し、アーカイブ更新や外部変更の扱いが曖昧になるため採用しない。
- 形式指定時だけ閲覧専用の安全モードにする: 通常ファイルと挙動が変わり、利用者が期待する編集や更新を妨げるため採用しない。

## Consequences

拡張子に依存する WasabiPad 内の判断は、実パスの末尾ではなく有効拡張子を一貫して参照する必要がある。一方、保存、Windowsアプリ、既定ブラウザ、エクスプローラ、登録コマンドへ渡すパスは実パスを維持する。ZIPと7zの更新は元の実ファイルへ書き戻し、形式指定は別項目へ移動した時点で破棄して再起動後へ保存しない。画像形式の自動判別は、メモリ使用量を抑えるため上限付きの内容検査として実装する。指定形式の単体画像/PDFはMIMEを確実に伝えるためBlobへ読み込むが、資産読込には32MiBの上限を設け、超過時は表示を失敗させて原本を変更しない。
