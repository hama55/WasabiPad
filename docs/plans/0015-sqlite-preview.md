# SQLiteプレビュー実装計画

## 状態

設計合意済み。実装・依存追加・サイズ計測は未実施。この文書を実装担当AIへの依頼書とする。

## 目的

`.sqlite` と `.sqlite3` の保存済み実ファイルを、既存の標準プレビュー領域で読み取り専用に確認できるようにする。テーブルの選択、列とレコードの閲覧、SQLite内部オブジェクトの確認を可能にし、DBを変更しない。

## 確定した仕様

- SQLiteエンジンはRust側の `rusqlite` を使う。`default-features = false` と `bundled` だけを有効にし、外部sqlite3.exe、WASM、Tauri SQLプラグインは使わない。
- 対象は大文字小文字を区別しない `.sqlite` と `.sqlite3` の保存済み通常実ファイルだけ。未保存文書、アーカイブ内項目、仮想項目は対象外。
- 接続は読み取り専用。固定したSQLite照会だけを実行し、利用者が任意SQLを入力・実行する入口、編集、保存、エクスポートは作らない。DBのコピーやキャッシュも作らない。
- 選択欄には、通常テーブル、ビュー、仮想・シャドウ・`sqlite_`内部テーブルを隠さず表示する。`sqlite_schema`も選択可能にし、索引・トリガー定義は同テーブルの行として確認する。専用のスキーマ画面は作らない。
- 初期選択は通常テーブルを優先し、なければ先頭の選択可能な項目にする。表示順はSQLiteの取得順であり、行順を保証しないことを表示する。
- `NULL`は明示表示、BLOBはバイト数表示、長い文字列は4,096文字で省略する。BLOB専用ビューアは作らない。
- 設定名は「SQLiteプレビューの表示行数」。初期値100、正の整数、設定上限なし。初回と「さらに表示」は設定値ごとに行を追加する。DOMへの追加だけは200行単位に分割して、画面停止を抑える。
- 設定変更は次回プレビューまたは再読み込みから反映する。自動更新はしない。開いた時点の読み取り専用スナップショットを表示する。
- WAL/SHMは元ファイル横にあるものをSQLite標準の読取に任せる。ロック、破損、暗号化、WALを読めない状態、対象外のデータベースは、理由と再読み込み操作をプレビュー領域へ表示する。

## 実装手順

1. 実装前の基準として、同じ作業ツリーでexeとNSIS installerのバイト数を記録する。
2. `core` に `rusqlite` を最小構成で追加し、読み取り専用のSQLite照会モジュールを作る。Tauri層に依存させず、パス、選択対象、表示行数からプレビューDTOを返す。
3. SQLiteの識別子は安全に引用し、表示行数はバインド値で渡す。書込み可能な接続フラグ、拡張ロード、任意SQL実行は追加しない。
4. Tauri commandと生成IPC契約を追加する。`ui/generated/`は既存の生成手順で再生成し、手編集しない。
5. `viewer-formats`、通常プレビュー開始経路、InlinePreview payload、viewer rendererへSQLite形式を追加する。CSV rendererのパーサーや本文位置同期は流用せず、表のCSS・行番号・列幅変更だけを再利用する。
6. プレビュー上部に選択欄、再読み込み、現在の表示件数、さらに表示を置く。値の表現、理由表示、200行単位のDOM追加をSQLite専用rendererに実装する。
7. 既存の設定型、復元時検証、設定モーダルのプレビュー節、数値入力、保存経路を再利用する。数値入力はmax属性なしを表せる最小変更に留める。
8. 依存追加と最小読取が動いた時点で、再度exeとNSIS installerを同じ手順でビルドしてバイト数を比較する。どちらかが基準から1MiBを超えて増えた場合は、増分を報告して作業を停止し、利用者の明示判断を待つ。1MiB以下なら残りのUI実装へ進む。
9. 実装完了時に `docs/adr/0015-...` を追加し、`0014-skip-sqlite-preview.md` を履歴として残したまま、この採用判断を明示的に上書きする。`CONTEXT.md` の既存「SQLiteプレビュー」用語はそのまま使う。

## BDD受入条件

- Feature: SQLite形式の通常実ファイルをプレビューする
  - Scenario: `.sqlite` または `.sqlite3` の保存済み実ファイルを開くと、標準プレビューでSQLiteの選択欄とレコード表を表示する。
  - Scenario: 未保存文書またはアーカイブ内項目を開くと、SQLiteプレビューを開始しない。
- Feature: SQLite内容を変更せず確認する
  - Scenario: テーブル、ビュー、`sqlite_schema`を選択すると、対応する列とレコードを表示する。
  - Scenario: 読み取り後もDBファイルの内容は変更されない。
  - Scenario: `NULL`、BLOB、長文を定義どおり表示する。
- Feature: 設定した行数を段階表示する
  - Scenario: 初期値100を使うと100行までを表示する。
  - Scenario: 正の値を保存すると次回再読み込みからその件数で表示し、さらに表示で同じ件数を追加する。
  - Scenario: 上限なしの設定値でもDOMは200行単位で追加する。
- Feature: 読めないSQLiteの理由を表示する
  - Scenario: 破損、暗号化、ロックなどで開けないと、プレビュー領域に理由と再読み込み操作を表示する。

## 検証

- SQLite読取モジュール、viewer renderer、設定、IPC契約に対応するBDDテストを、既存の対象モジュールと同じ場所へ追加する。
- `npm test`、`npx tsc --noEmit`、既存のIPC生成・契約チェック、`npm run build`、`git diff --check` を実行する。
- 実際のWindows成果物としてexeとNSIS installerを比較し、基準値・新値・増分を報告する。

## 非対象

- `.db`、アーカイブ内SQLite、未保存SQLite、SQLコンソール、編集・保存・エクスポート、検索・並べ替え・絞り込み、BLOB専用ビューア、DBコピー・キャッシュ、外部sqlite3.exe、WASM、Tauri SQLプラグイン。
