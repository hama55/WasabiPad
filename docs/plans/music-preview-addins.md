# 楽譜プレビューアドイン — 設計検討

状態: 設計方針合意済み（2026-09-26）。ローカル実装・自動試験・LilyPond CLI検証済み。配布先への公開とWebView上の発音確認は未実施。

## 合意済み要件

- 対象はWasabiPad向け公式アドインに限り、独立した.abcと.lyを扱う。Markdown埋め込みは対象外。
- 初回から両形式の編集・楽譜表示・WasabiPad内での音再生を提供する。PDF保存は対象外。
- 設定画面の公式一覧からダウンロードして追加する。アドイン管理の操作は追加・有効/無効・削除・手動更新。更新失敗時は旧版を維持する。
- アドイン・音源・LilyPond導入後は、表示と再生を完全オフラインで利用できる。LilyPond本体は同梱せず、利用者が別途インストールする。
- ABCは入力後に表示を自動更新する。LilyPondは利用者が表示更新を操作したときだけ実行し、文書を開いただけでは実行しない。
- 再生は先頭からの再生と停止のみ。位置指定・テンポ変更・音符ハイライトは初回対象外。
- 譜面に複数の曲がある場合は全曲・全ページを表示し、曲一覧で選んだ曲をその先頭から再生する。
- 保存済み主ファイルからのローカル別ファイル参照を扱う。主ファイルは未保存の編集中内容、参照先はディスク上の保存内容を使う。無名の新規文書で相対参照を使う場合は先に保存を案内する。
- LilyPond入力に\midi {}がなくMIDIを生成しない場合は譜面表示のみとし、再生用記述の追加方法を案内する。ソースは自動変更しない。

## 着手前の状況と検討前提

- 現行プレビューは対応形式を固定しており、後付けアドインを読み込む機構はない。設定画面と既存プレビュー領域は再利用候補。
- Tauriプラグインはアプリ側で組み込む開発者向け機構のため、利用者が後から追加するアドインの入口・配布は別途設計する。[Tauri公式資料](https://v2.tauri.app/develop/plugins/)
- ABCJSは音源の場所を指定でき、音源読込後の再生準備にはネットワーク接続を要しない。導入済みのローカル音源を使う構成ならオフライン利用できる。[ABCJS公式資料](https://docs.abcjs.net/audio/synthesized-sound)
- LilyPondは\midi {}でMIDIを出力する。譜面表示と音再生には別の経路が必要。[LilyPond公式資料](https://lilypond.org/doc/v2.24/Documentation/notation/the-midi-block)
- LilyPond入力はSchemeを含み実行し得るため、アドイン形式と実行境界の設計が必要。

## 技術検証前提（着手前の調査記録）

- 現在の版はRust側Tauri 2.11.5（src-tauri/Cargo.lock:3330）、JS API 2.11.1（package-lock.json:1069）、CLI 2.11.4（package-lock.json:1079）。
- Asset protocolは有効でscopeは`**`（src-tauri/Cargo.toml:12、src-tauri/tauri.conf.json:24-28）。独自URI protocolの登録はない。
- 現行CSP（src-tauri/tauri.conf.json:30-42）はconnect-srcがIPC系のみで、media-srcとworker-srcの明示指定がない。default-srcはself/customprotocol/asset。現状のままではフロントから公式配布サイトへ直接取得する経路は使えない。HTMLプレビューのmedia許可は別iframe用で、音再生成立の証拠にしない。
- インラインプレビューはui/inline-preview.ts:63、別窓プレビューはsrc-tauri/src/viewer.rs:116のWebviewUrl::App。共通capabilityはsrc-tauri/capabilities/default.json:4-6。
- PATHとProgramFiles・ProgramFiles(x86)・LocalAppDataの一般的な場所ではLilyPond実行ファイルを確認できていない。未導入とは断定せず、検証用実行ファイルの確保（別場所の既存導入先指定または公式版の検証用準備）が前提。--versionは未実行。
- 実機での動作と音再生は未検証。

## 合意した構成方針

- 本体は公式一覧・導入状態の管理、既存プレビュー起動と形式切替の共通経路からのアドイン呼び出し、導入済み資産の読み取り、外部ツール実行、生成物の受け渡しを担当する。既存6形式を全面的にアドインへ移行しない。ABC・LilyPondのライブラリと音源は各追加パッケージに置き、本体の標準配布に含めない。共通音源基盤は初回対象外。
- 既存のインライン・別窓プレビューを使う。ABCはabcjsで描画・再生する。LilyPondは利用者が導入したCLIでSVGとMIDIを生成し、アドインがSVG全ページ表示とMIDI再生を担当する。MIDI再生ライブラリ・音源・対応LilyPond版は技術検証で決める。
- LilyPondのMIDI再生はspessasynth_lib（Apache-2.0）を第一評価候補とするが、採用は未確定。[spessasynth_lib](https://github.com/spessasus/spessasynth_lib)の代わりにMIDIをABCJS SynthSequence向けに独自変換する案は、テンポ・イベント処理を抱えるため第一案にしない。
- Tauriの両プレビュー経路でローカルworklet・音源・MIDIが動くか、音源の配布条件と追加容量、テンポ変化・多声部・楽器設定を確認してから採否を決める。
- MIDI出力の有無はソース文字列の検索でなく生成物で判定する。曲名を取得できない場合はファイル名など識別できる表示名を付ける。複数book・scoreのSVGとMIDIの出力名・順序の対応は実機検証の必須項目。
- 公式アドインは信頼された実行コードとして扱い、任意Rust DLLの後付けと第三者アドインは対象外とする。iframeだけで安全に隔離できるとはみなさず、本体へのアクセス窓口を絞るが、厳密なサンドボックスは保証しない。LilyPond楽譜はSchemeを実行でき、手動更新はサンドボックスの代わりにならない。初回実行前に、信頼する楽譜だけを生成する旨を案内する。
- 公式の固定配布先から取得し、パッケージの整合性と互換性を確認してから導入する。展開先外へのパスは拒否し、一時領域で準備後に切り替える。導入・更新失敗時は旧版を維持する。削除対象はアドインとその生成物に限り、利用者の楽譜や外部LilyPondは削除しない。未導入・無効・非互換・外部ツール未検出を区別して設定への導線を示す。オフラインでは導入済み機能を使い、公式一覧を取得できないことを明示する。
- LilyPond実行ファイルは自動検出と設定でのパス指定を用意する。プロセスはシェル文字列でなく引数配列で起動し、ジョブごとの出力領域を設ける。生成物の読み取りはその領域内に限定し、中止とタイムアウトを提供する。利用者ソースは書き換えない。
- ローカル実装では過大な生成物からアプリを守るため、1回のLilyPond生成をSVG・MIDI計256ファイル、合計64 MiBで止める。超過時は一部のページを成功扱いせず、上限超過を示す。全ページ・全曲表示はこの資源上限内の譜面を対象とし、上限引き上げは実利用例を確認して判断する。
- 表示元は編集中の主ファイルのスナップショットとする。文書・版・生成要求を対応付け、切替前や古い処理の結果を新しいプレビューへ混入させない。編集・文書切替・プレビュー終了・アドイン無効化・削除時には再生を停止する。編集後は譜面を「未更新」と表示する。生成失敗時は前回成功結果を「更新失敗・前回結果」として残すが、未更新または失敗後の古い結果は再生不可とし、生成成功後も自動再生しない。

### V3 LilyPond CLI実測（部分合格）

公式Windows ZIP（45,581,453 B、SHA256 `14DDDDC233B469EF60D4FFC1C7F35520F15AC6B58E38CAB458C60BDCC3AF650C`）を一時領域へ展開して実行。`--version` は `GNU LilyPond 2.26.0 (Guile 3.0)`。自作fixtureを `-fsvg -o OUTPUT INPUT` で処理し、相対includeには `-I SAVED_INCLUDE_DIR` を指定した。日本語・空白を含むパス、保存済み相対include、主ファイルのbuffer snapshotを含む全fixtureが終了コード0。元ファイルのSHA256は実行前後で不変。警告はFontconfig cacheのみ。

| 入力構造 | 実測出力 |
| --- | --- |
| 1 score・1 page | SVG 1、MIDI 1 |
| 2 books・各1 score・各2 pages | SVG 4、MIDI 2。Alphaは`output.mid`と`output-1.svg`・`output-2.svg`、Betaは`output-1.mid`と`output-1-1.svg`・`output-1-2.svg`。 |
| 1 book・2 scores | SVG 1、MIDI 2。Alphaは`output.mid`、Betaは`output-1.mid`。 |
| MIDIなしscore | SVG 1、MIDI 0 |

リポジトリへ追加した4つの`.ly`も同じCLIで一時領域へ生成し、全件終了コード0。出力件数は表どおりで、2 books・2 scoresの両方でMIDI内のAlpha/Betaと出力名が対応した。この実行ではFontconfigが書き込み可能なcache directoryなしを報告したが、全出力を生成した。

この単体実測だけではV3全体の合格にならない。後続の本番試験で構文エラー時の扱いとWasabiPadへの統合を確認した。両WebViewでの表示・音再生と公式アドインの実ダウンロードは未検証。

現在の本番CSPを基準に拒否される経路を特定し、必要な場合は最小限の変更案を個別に評価する。CSP全許可やasset scopeの安易な拡大で通さない。公式配布取得は本体Rust側経路を第一候補として確認し、URLと通信許可は詳細設計で確定する。検証は分離したcheckout・専用データ領域・自作fixtureで行い、日常利用の楽譜や設定を上書きしない。

証跡として、OS・WebView2・Tauri・各library・LilyPond・fontの版、入力fixture、機密情報を含まないコマンドと引数、SVG/MIDI出力一覧、譜面画像、再生・停止確認、外部通信の有無、生成時間・配布容量、成功・失敗・未検証の判定と再現手順を残す。スクリーンショットだけで音再生成功とは判定しない。実音の自動確認ができない場合、聴取確認が必要な項目は未検証とする。

ゲートはV1 → V2/V3/V4 → V5/V6の順とし、独立作業は並行できる。本実装は親が検証結果を採否判断し、asset配信/API・状態契約・library/font・対応版・timeout等を具体化してから始める。検証不成立時は親へ戻す。実装担当が独断で片方の形式・音・複数曲・offline要件を削らない。仕様の重要変更のみユーザーと再合意する。

## ローカル実装で確定した事項

- 公式一覧はWasabiPadの固定GitHub配布先から取得し、各公式ZIPのSHA-256、対応アプリ版、内容と展開先を確認する。アドインは利用者データ領域に置き、追加・無効化・削除・手動更新を設定画面から操作する。版の切替失敗時は旧版を維持する。
- 本体は導入済み資産だけを`wasabi-addin`ローカルプロトコルから提供する。ABCはabcjs 6.7.0と同梱MP3音源、LilyPondのMIDI再生はspessasynth_lib 4.3.14と同梱SF3音源を各ZIPに収め、本体の通常ビルドには含めない。
- LilyPondは利用者が別途導入した実行ファイルをPATHなどから検出し、必要なら設定パスを使う。更新操作時だけ編集中の主ファイルを一時領域で処理し、保存済み主ファイルの場所から相対参照を解決する。生成を30秒で打ち切り、SVG・MIDI・診断出力に上限を設ける。
- Rust・UIの自動試験とLilyPond 2.26.0を使う生成試験は成功した。WebView2上の資産読込・発音・停止、および公開済み公式配布先からの実ダウンロードは未検証。アドインZIPはローカルで生成済みで、公式配布先へは未公開。

## 工程

1. 合意済み要件と合意した構成方針の共有理解を確認する。今回の設計方針は合意済み。
2. 上記のV1〜V6をゲート順に技術検証する。親が結果を設計へ反映する。
3. アドイン形式・入口・配布検証・実行境界・状態・ライブラリ等を実装担当が迷わない仕様として確定する。重要な変更があればユーザーと再合意する。
4. 実装着手後、BDDで最小基盤を作り、ABC表示・再生、LilyPond表示・再生の順で進める。
5. オフライン、導入失敗、古い結果の混入、再生停止を含めて確認する。
6. レビュー後、親agentがcommitする。

## 本番BDD

技術検証試作の成功は本番BDDの代わりにしない。既存のBDD対象を維持し、設定UI、導入・更新rollback、全プレビュー入口、未導入・無効・非互換・外部ツール未検出を本体統合で確認する。

BDD対象: 既存6形式の挙動維持、未導入と無効の案内、公式導入と手動更新失敗からの復旧、導入後ネット接続なしで両形式の表示・再生、未保存の主文書と保存済み参照先、複数曲・複数ページ、MIDI生成物の有無判定と曲名がない場合の表示、複数book・scoreのSVG/MIDI対応、文書を開いただけではLilyPondを実行しないこと、MIDI出力なしでも譜面を表示すること、古い非同期結果の排除、更新失敗時の表示、文書切替などでの再生停止、外部ツール未検出・終了失敗・中止・タイムアウト、パッケージと生成物のパス逸脱拒否。

設計と工程管理は親agentが行う。調査・実装などはCLAUDE.mdに従いsubagentへ委譲する。ローカルのアプリ実装は済み、本計画の両WebView表示・音再生の実機検証は未実施。
