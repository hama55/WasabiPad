# 貼り付け画像の即時プレビュー

## 合意した動作

- 編集可能な文書は拡張子を問わず、画像貼り付けから開くMarkdownプレビューで画像を表示する。
- 貼り付け後の文書保存・アプリ再起動を表示の条件にしない。
- 連続貼り付け、md文書、別のフォルダの文書へ切り替えた後も、現在の文書の場所から画像参照を解決する。

## 原因と修正

画像保存は完了しているが、エディタから直接Markdownプレビューを開く経路では画像参照元の文書パスを設定していなかった。通常のプレビューを開く経路では設定されるため、再起動後には画像を表示できた。

直接Markdownを開く場合も、現在の文書の保存場所とアーカイブ情報をプレビューに渡してから本文を送る。通常のプレビュー切替で決定済みの参照元は維持する。

## 検証境界

- mainの接続確認: 直接Markdownを開く前に現在の文書の参照元が設定される。
- InlinePreviewの公開操作: 初回open、連続update、別文書のopenで送るpayloadと、その画像相対パスの解決先を確認する。txt、md、任意拡張子を対象にする。
- 既存の画像貼り付け、プレビュー、画像パス解決テストを実行する。
- mainの接続確認は既存方式の静的検査であり、実アプリのCtrl+Vによる画像表示の確認とは区別する。

## 検証結果

- 接続確認を先に追加し、修正前の失敗と修正後の成功を確認した。
- 対象4ファイルの202テスト、全体107ファイルの1,161テスト、TypeScript型チェック、差分チェックが成功した。
- 実TauriアプリでのCtrl+V直後の画像表示は未確認。
