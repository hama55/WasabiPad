# SQLiteプレビュー上部の省スペース化

状態: 合意済み・実装済み・自動検証済み（2026-10-11）。実機確認は未実施。

## 目的

SQLiteプレビューの上部固定領域を短くし、データ表示領域を広げる。

## 確定した仕様

- 「SQLite一時ビュー」を既存のビュー定義と同じ開閉UIにし、初期状態は閉じる。閉じている間は見出し1行だけ表示する。
- SQL入力欄、説明文、実行ボタンを折り畳み内に置く。
- 結果順の注意文は「表示上の注意」として別の開閉UIにまとめ、初期状態は閉じる。
- 両方の開閉状態は現在のプレビュー内だけ保持する。全画面切替でも保持し、プレビューを閉じて開き直したら初期状態へ戻す。永続設定は追加しない。
- 開閉では入力SQL、実行済みSQL、表示対象、結果、ページキャッシュ、表のスクロール位置を変更しない。
- SQL実行中も開閉できる。成功しても自動で閉じず、手動の開閉状態を保持する。
- SQLエラーは折り畳みの外に表示する。失敗時は以前の成功結果を保持する。
- 開閉による表の高さ変更に合わせて仮想表の表示範囲を再計算する。実行中の開閉も既存の再描画予約経路で処理する。
- キーボードから開閉でき、開閉状態が支援技術に伝わる既存のdetails/summaryを使う。

## 接続点

- `ui/viewer-sqlite.ts`: 入力フォーム・注意文の開閉UI、既存scheduleRenderへの接続。
- `ui/viewer.css`: 既存フォーム配置・開閉UIの見た目を再利用し、必要な範囲だけ調整。
- `ui/viewer-sqlite.test.ts`: 開閉と結果保持、表の再描画のBDD。
- 全画面切替ではプレビューを再生成しない既存経路を維持する。

## BDD受入条件

1. Given 新しく開いたSQLiteプレビュー、When 初期表示する、Then 一時ビュー入力と表示上の注意は閉じており、見出しから開ける。
2. Given 入力SQLと表示結果がある、When 各領域を開閉する、Then 入力・実行済みSQL・結果・表示対象・スクロール位置を保持する。
3. Given SQL実行中、When 入力欄を閉じて成功する、Then 新しい結果を表示し、入力欄は閉じたままになる。
4. Given SQL実行中と以前の成功結果、When 入力欄を閉じて失敗する、Then エラーが外側に表示され、以前の結果を保持する。
5. Given 入力欄が開いている、When 閉じて表の領域が広がる、Then 新しい高さに必要な行を描画する。実行中でも完了後に再描画する。
6. Given 任意の開閉状態、When 全画面を切り替える、Then 開閉状態と結果を保持する。When プレビューを閉じて開き直す、Then 両領域は閉じる。
7. Given 見出しにキーボードフォーカスがある、When 開閉操作する、Then マウスなしで開閉できる。

## 非対象

- ツールバーの操作配置変更、開閉状態の永続化、新しい状態バッジ。
- SQL実行条件、バックエンド、IPC、DBへの読み書き方針の変更。
- 用語の再定義と新しいADR。既存のSQLite一時ビューの意味と安全性の判断を維持する。

## 検証

- BDDを先に追加し、対象テスト、TypeScript検査、差分検査を実施する。
- 実機では通常表示・全画面・狭い幅で、上部の高さ、操作、エラーの見え方、データ表示を確認する。自動検証と実機確認の結果を分けて報告する。

### 実施結果

- 初期閉と、開閉後の表示行数追従について、追加BDDの失敗を確認してから実装し成功を確認。
- 対象テスト: SQLiteプレビューとInlinePreview、2ファイル65テスト成功。
- 全体テスト: 112ファイル1249テスト成功。
- TypeScript検査、Viteビルド、差分検査成功。ビルド時の500 kB超チャンク警告あり。
- 規約レビュー、仕様レビューともに指摘なし。
- 実機の通常表示・全画面・狭幅、キーボード開閉、支援技術の読み上げは未確認。キーボードと開閉状態通知は標準details/summaryを利用する。
