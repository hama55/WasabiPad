# SQLiteプレビューの一時ビュー

状態: 実装・検証済み

## 目的

SQLiteプレビューで単一の読み取り用 `SELECT` を入力し、その結果を既存のSQLite表として一時的に確認できるようにする。定義はアプリやDBへ保存しない。

## 確定した仕様

- SQL入力欄と「一時ビューを表示」操作をSQLiteプレビューに置く。
- 先頭が `SELECT` の単一の読み取り用SQLだけを受け付ける。`WITH`句、複数ステートメント、DDL、DMLは受け付けない。
- 一時ビューは一つだけとする。新しいSQLの読取が成功した時にのみ現在の表示を置き換え、失敗時は成功済みの表示を残してエラーを示す。
- 入力SQLと成功済みのSQLは、現在のプレビューコントローラーのメモリだけに持つ。設定・文書・元DBには保存しない。プレビューを閉じると破棄する。
- 各ページ要求で従来どおり元DBを読み取り専用で開き、接続内に `temp_store=MEMORY` のTEMP VIEWを再作成する。接続を常駐させず、既存の正確な総行数表示とページングを使う。
- 複雑なSQLは総行数計算と表示ページ取得で複数回評価されうる。要求ごとに接続を開き直すため、外部DB更新後に新しく取得したページが以前の結果と異なる場合がある。SQLに `ORDER BY` がなければ順序は保証しない。

## 接続点

- `core/src/sqlite_preview.rs`: 任意SQLを一時ビューとして作成し、既存の安全な識別子引用、COUNT、LIMIT/OFFSET、セル表現を流用する。
- `src-tauri/src/main.rs`、`ui/api.ts`: 各読取要求に任意のSQLを渡す既存IPCを拡張する。
- `ui/viewer-sqlite.ts`: SQL入力、成功時の置換、失敗時の前回表示保持、ページ要求への成功済みSQLの引き継ぎを実装する。
- `ui/viewer-sqlite.test.ts`: UIコントローラーの公開操作で成功・失敗・ページング中のSQL保持を確認する。

## BDD受入条件

1. Rust公開関数に対して、読み取り専用SQLiteファイル上のSELECT結果がページングされ、元DBのバイト列が変わらないことを確認する。
2. 複数ステートメントや書き込みSQLを拒否し、元DBを変えないことを確認する。
3. UIコントローラーに対して、有効なSQLの成功後に一時ビューの結果とSQL定義を表示し、次ページにも同じSQLを渡すことを確認する。
4. 新しいSQLが失敗した場合にエラーを表示し、直前に成功したビューとそのページング用SQLを維持することを確認する。

## 非対象

- DBの更新、保存、SQL定義の永続化、複数の一時ビュー、SQL編集履歴、ソートUI、スナップショット。
- SQLiteプレビューの接続常駐化、DBコピー、外部SQLエンジン・依存ライブラリの追加。

## 検証

- RustのSQLiteプレビュー対象テストとUIコントローラーテスト。
- IPC生成・契約確認、UIテスト、TypeScript型チェック、Rustチェック、差分空白検査。
- 自動検証では実アプリのネイティブ画面操作を確認しない。
