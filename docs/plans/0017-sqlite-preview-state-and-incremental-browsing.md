# SQLiteプレビューの状態保持と段階閲覧の実装計画

## 状態

設計済み。実装は未着手。この文書を実装担当AIへの依頼書とする。

先に [SQLiteプレビュー: 閲覧専用実ファイルの読取元修正計画](./0016-sqlite-view-only-source-path.md) を実装する。本計画は、通常実ファイルのSQLiteプレビューが開始できることを前提にする。

## 目的

SQLiteプレビューで、全画面切替後も選択中のテーブルまたはビューを見失わず、ビューの定義・総行数・任意の表示位置を確認できるようにする。数千行以上でも「さらに表示」を繰り返さず、縦スクロールに応じて必要な行だけを読む。

## 確定した仕様

### 状態と全画面

- 全画面化・復元は、既存iframeへ全画面状態だけを通知する。SQLite preview payloadは再送しない。
- 同じプレビューを閉じるまで、選択対象、表示位置、縦スクロール位置、横スクロール位置、読込済みのページを維持する。
- 再読み込み、ファイルを閉じる、再オープンでは状態を復元しない。初期選択規則に戻る。

### 表、ビュー、総行数

- テーブル、ビュー、SQLite内部オブジェクト、`sqlite_schema` の既存選択対象はすべて引き続き表示する。
- ビュー選択時は、結果の表に加えて、選択欄の直下に「ビュー定義」開閉部を置く。内容は `sqlite_schema` に保存された対象ビューの `CREATE VIEW ...` SQLをそのまま表示する。
- JOIN先をグラフ・ツリー・リンクへ解析しない。利用者は定義SQLと結果表で確認する。
- 選択または再読み込み時に `COUNT(*)` を実行し、取得中は「行数を計算中…」、完了後は `表示中 N / 全 M 行` と表示する。総行数が取得不能な場合は理由を表示し、表の閲覧自体は可能な限り続ける。
- 総行数は選択・再読み込み時だけ取得する。スクロール、追加ページ、表示位置移動で毎回 `COUNT(*)` を実行してはならない。

### 段階読込と表示位置移動

- 設定「SQLiteプレビューの表示行数」は、初回読込、下端接近時の読込、表示位置移動時に取得するページサイズとする。既定値100、正の整数、上限なしを維持する。
- 「さらに表示」ボタンは削除する。表示領域の下端へ近づいたら次の範囲を自動取得する。
- 大量行では、可視範囲とその前後の少量の余白だけをDOMに保持する。上部・下部の余白要素で全体のスクロール位置を表現し、範囲外の行DOMは破棄できるようにする。
- 固定高の1行表示を使う。既存のBLOB表示、NULL表示、4,096文字省略を維持し、セルの折返しを新たに導入しない。これにより行の位置と仮想的なスクロール高さを一致させる。
- 表の上部に1始まりの数字入力「表示位置へ移動」と実行操作を置く。1から総行数までの整数だけを受け付け、対象範囲を取得してその行を先頭付近へ表示する。
- 取得順は現在のSQLite照会順であり、恒久的な行番号ではない。入力欄の近くに「現在の結果順の位置です。再読み込みやDB更新後に同じ行を指す保証はありません」と常時表示する。
- テーブルへの強制 `ORDER BY rowid`、主キー推測、ビューSQLの `ORDER BY` 解析、利用者による並び替えは追加しない。
- DBを外部で変更しても自動再読込しない。新たに取得する範囲はその時点の読取結果となり、既表示範囲とのずれを許容する。DB接続の常駐、コピー、キャッシュは作らない。

## 実装方針

既存のSQLite読取commandはすでに選択名、`offset`、`limit` を受け取り、`LIMIT` / `OFFSET` で1ページを返せる。この経路を使い、任意SQL用API、外部依存、巨大テキスト用 `VirtualEditor` は追加しない。

### DTOとIPC

- SQLiteプレビュー応答へ、必要な場合だけ返す `totalRows` と `viewDefinition` を追加する。
- 初期選択、対象変更、再読み込みではメタデータ取得を指定し、Rust側は対象の `COUNT(*)` と、対象がviewの場合だけ `sqlite_schema.sql` を返す。
- 自動読込と表示位置移動ではメタデータ取得を指定しない。既に表示している総行数とビュー定義を再利用する。
- 型とcommand引数を変更した場合、既存の生成手順で `ui/generated/` を再生成する。生成物を手編集しない。

### renderer

- `viewer-sqlite.ts` に、選択対象ごとの表示状態とページキャッシュを持たせる。状態はiframe内だけに置き、親画面へSQLite専用状態を追加しない。
- 全画面切替では `InlinePreview.setFullscreen()` がSQLite payloadを再送しないようにする。既存の `FULLSCREEN_STATE_MESSAGE` を受ける処理は、全画面ボタン表示の更新だけを続ける。
- スクロール領域に上下スペーサーと行ウィンドウを置く。スクロール位置から必要なページ範囲を算出し、未取得ページだけを既存IPCで要求する。多重要求は同一ページにつき1件に抑え、失敗時は同じ範囲を再試行できる表示にする。
- `IntersectionObserver` を使える既存パターンがあれば下端接近の検知に再利用する。なければスクロール位置計算だけで完結させ、新しい共通抽象化は作らない。
- 表示位置移動では入力値を検証し、対象ページを要求してスクロール位置を更新する。範囲外、空、整数でない入力は既存のプレビュー内エラー表現で伝える。

## BDD実装順

各段階で先に失敗するテストを追加し、最小実装でgreenにする。リファクタリングは全BDDがgreenになってから必要な場合だけ行う。

2. `core/src/sqlite_preview.rs`
   - Feature: SQLite対象の閲覧メタデータを取得する
   - Scenario: テーブルを選択してメタデータ取得を指定すると、ページ結果と正確な総行数を返す。
   - Scenario: viewを選択すると、結果行、総行数、`CREATE VIEW` 定義を返す。
   - Scenario: 追加ページを要求すると、`COUNT(*)` とview定義を再実行せず、指定されたoffset/limitの行だけを返す。
   - Scenario: `sqlite_schema` と内部テーブルは従来どおり選択・閲覧できる。

3. `ui/viewer-sqlite.test.ts`
   - Feature: SQLiteビューを確認する
   - Scenario: viewを選択すると、結果表と展開可能なビュー定義を表示する。
   - Feature: SQLiteを段階的に閲覧する
   - Scenario: 初期表示は設定値100の範囲だけを要求し、総行数を上部に表示する。
   - Scenario: 下端に近づくと、ボタン操作なしで次の未取得ページを1回だけ要求する。
   - Scenario: 多数行でも可視範囲外の行DOMを残さない。
   - Scenario: 「表示位置へ移動」に5001を入力すると、その周辺を要求して表示する。
   - Scenario: 0、総行数超過、非整数は要求せず理由を表示する。
   - Scenario: 順序が恒久的でない注意書きを表示する。

4. IPC型を変更した場合は `scripts/check-ipc-contract.mjs` の既存チェックをgreenにし、生成型の同期を確認する。

## 実装手順

1. 作業ツリーを確認し、先行計画0016を実装・検証する。未完了なら本計画の手前で止める。
2. 全画面切替のBDDを追加し、payload再送をやめる最小変更を行う。SQLite controllerが再生成されないことを確認する。
3. Rust読取DTO・requestへメタデータ取得指定を最小限追加し、`COUNT(*)`、view定義、ページ要求をBDDで実装する。識別子の既存安全引用と読み取り専用接続を維持する。
4. IPC契約と生成型を正規手順で同期し、rendererから初期・対象変更・再読み込み時だけメタデータを要求する。
5. 既存SQLite rendererに総行数、ビュー定義、順序注意書き、表示位置入力を追加する。`さらに表示`のUIとイベントを削除する。
6. SQLite専用の小さな表示ウィンドウを実装する。初期ページ、下端接近、自動追加、上端への戻り、表示位置移動、失敗再試行をBDDで確認する。
7. CSSを既存CSV/SQLite表の見た目へ最小限追加し、固定行高、縦横スクロール、上下スペーサー、狭い画面での操作部の可読性を確認する。
8. 手動で、通常テーブル、JOINを含むview、`sqlite_schema`、数千行の表を確認する。全画面化・復元で同じ対象と位置が残ること、スクロールだけで続きが読めること、表示位置移動が動くことを確認する。

- `ui/viewer.ts`: 全画面状態メッセージ受信時の更新を維持し、SQLite rendererの再生成を防ぐ。

- `ui/viewer-sqlite.ts` と `ui/viewer-sqlite.test.ts`: 状態保持、ビュー定義、総行数、表示位置移動、段階読込、表示ウィンドウ。

## 非対象

- DB編集、保存、エクスポート、任意SQL、検索、絞り込み、ソートUI。
- JOIN依存グラフ、SQL解析、対象テーブルへのリンク。
- 永続的な表示状態、DBコピー、キャッシュ、常駐DB接続、一貫した読取スナップショット。
- `.db`、アーカイブ内SQLite、実パスを持たない新規文書、BLOB専用ビューア。
- 巨大テキスト用 `VirtualEditor` の流用、外部ライブラリの追加。
