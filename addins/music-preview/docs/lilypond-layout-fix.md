# LilyPond 配置崩れの修正・検証（2026-10-03）

## 原因と変更

`cursor.ily` が NoteHead / Rest の `after-line-breaking` から System の Y 境界を取得していた。配置確定前の境界評価が配置計算に干渉し、上下の五線を離して隣の段と重ねていた。音符座標を先に評価するだけでは再現結果は変わらなかった。

追加属性を `output-attributes` の遅延 callback で返すように変更し、System の境界取得を描画時まで遅らせた。原稿側の `after-line-breaking` を変更せず、既存の属性 list / callback は未評価で保持する。入力楽譜と演奏内容は変更しない。

LilyPond 2.26.0 の処理順序は [System の後処理](https://raw.githubusercontent.com/lilypond/lilypond/v2.26.0/lily/system.cc)と[描画属性の評価](https://raw.githubusercontent.com/lilypond/lilypond/v2.26.0/lily/grob.cc)で確認した。

記譜用 score と MIDI 用 score が分かれる場合は、score ID の一致を保ち、曲順や音符番号から対応を推測しない。対応する描画 score がない場合は、音声を維持して「MIDI用 score に対応する記譜用 score を特定できません。」を表示する。
